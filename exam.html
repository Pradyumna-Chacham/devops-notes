What this means for studying: you never have to produce a definition or a line of code from memory. You have to recognise. Recognise which tool a snippet belongs to, recognise the one wrong word in a statement and know its replacement, and recognise which two ideas belong together. The definitions on the other pages still matter, because every true / false statement is a definition with a word swapped.

True / false with corrections

Instruction from the slides: "True or False (T or F). If a statement is false, identify how to make it true by underlining the word(s) you want to change and writing a new word(s) below the statement." No simple negation: "Lake Michigan is not made of salt water" does not earn points; underline "salt" and write "fresh".

How to answerFind the single term that makes the statement wrong and replace it with its partner term. Most false statements are built by swapping one member of a pair: develop / main, image / container, declarative / imperative, deploy / release, control node / managed node, left / right. If you find yourself wanting to write "not", look for the word to swap instead. A true statement just gets a T.

The samples shown in class

True / FalseIn DevOps, PR stands for pull requirement.
False. Underline requirement → request.
True / FalseA PR contains at most a single commit.
False. Underline at most a single commit → one or more commits.
True / FalseThe "two large pizzas" rule states that a DevOps pipeline should take less time to deploy than it takes for the team to eat two large pizzas.
False. The rule is about team size: a team should be no larger than two large pizzas can feed.
True / FalseIn a git flow paradigm, a feature branch is branched from main.
False. Underline main → develop.
True / FalseAnsible is mostly an imperative language.
False. Underline imperative → declarative.

Containers and computing environments

True / FalseThe docker -v option creates a temporary connection between a folder on the host and a folder in the container.
True. That is the bind mount.
True / FalseA bind mount copies a host folder into the image at build time.
False. It connects a host folder to a running container; nothing is copied into the image.
True / FalseSoftware installed by hand in a running container is saved in the image.
False. is saved in the image → is lost when the container ends. To keep it, add it to the Dockerfile.
True / FalseA container runs its own guest operating system kernel.
False. container → virtual machine (a container shares the host kernel).
True / FalseDocker is open source, while Podman is a closed-source commercial project.
False. Swap them: Podman is open source; Docker is closed source and commercial.
True / FalseBit rot occurs because the code changes while its environment stays the same.
False. Swap: the environment (dependencies) changes while the code stays the same.
True / FalseThe host is the operating system running inside the virtual machine.
False. host → guest.
True / FalseHardware-assisted virtualization works by patching the guest OS.
False. Hardware-assisted virtualization → Paravirtualization.
True / FalseAn environment variable lets you pass configuration to a program without changing its code.
True. Workshop 2 passed the token this way.
True / FalseAccess tokens should be committed to the repository so the pipeline can read them.
False. They should never be committed; pass them at run time or store them in a secrets manager.

Releases, rings, testing

True / FalseFeature flags enable features dynamically during production.
True. Glossary 1.
True / FalseDark launching makes deployed code immediately visible to all users.
False. immediately visible to all users → invisible to users.
True / FalseA canary release exposes the new version to all users at once.
False. all users at once → a small percentage of users first.
True / FalseA/B testing compares variants using a metric such as conversion rate.
True. 23% vs 11% on the slide.
True / FalseOne rollback option is to use the load balancer to shift traffic toward the canary.
False. toward → away from.
True / FalseDeflighting is a method for rolling back a defective change.
True. Deflighting or rollback, Glossary 1.
True / FalseStale feature flags reduce technical debt.
False. reduce → create.
True / FalseIn deployment rings, early adopters receive a change before canaries.
False. before → after.
True / FalseBlast radius is largest in the canary ring.
False. largest → smallest.
True / FalseShift-left reduces the cost of defects.
True. The slide's title.

False. shift-left → shift-right.

People, ownership, adages

True / FalseThe wall of confusion separates development from operations.
True. Software goes over the wall.
True / FalseIn the pre-DevOps era, the interface between development and operations was usually a pull request.
False. pull request → ticket system.
True / FalseChange ownership means developers are responsible for changes only during the development phase.
False. only during the development phase → for all phases (development, testing, deployment, fixing problems).
True / FalseA hotwash is another name for a retrospective.
True. Also postmortem.
True / FalseThe adage "Configuration is Code" is most closely tied to retrospectives.
False. retrospectives → Ansible / configuration management. (Retrospectives go with "Looking back to move forward".)
True / False"Be fast to release but slow to deploy" is one of the top ten adages.
False. Swap: be fast to deploy but slow to release.
True / FalseTelemetry instruments code to compute metrics about feature use, performance and stability.
True. Glossary 2.
True / FalseThe three goals of a retrospective are what worked, what didn't work, and who is to blame.
False. who is to blame → what can we do better.

Matching concepts

Instruction from the slides: "Connect the concept on the left to the most related concept on the right by drawing a line between them. Items on the left might not connect to anything on the right."

How the slide's example works

  • Red-Blue Trees
  • Gaussian Distribution
  • All-Pairs Shortest Path
  • Context-Free Grammars
  • Dijkstra's Algorithm
  • The GitHub Algorithm
  • Variance
  • Graph Algorithms
  • Theory of Computing
  • Data Structures
  • Statistics
  • Transformers
MatchingLines for the slide's example, and what it teaches
Red-Blue Trees ↔ Data Structures. Gaussian Distribution ↔ Statistics. All-Pairs Shortest Path ↔ Graph Algorithms. Context-Free Grammars ↔ Theory of Computing. Dijkstra's Algorithm ↔ Graph Algorithms. Variance ↔ Statistics. "The GitHub Algorithm" connects to nothing: it is a made-up distractor. "Transformers" on the right is never used. Lessons: a right-hand item can take several lines, a right-hand item can take none, and a left-hand item can be a decoy. Do not force a line.
How to answerGo down the left column. For each item ask "which category on the right does this belong to?" and draw one line to the most related item. If an item is invented or belongs to none of the right-hand items, leave it unconnected. Expect the right side to be the big buckets from the study guide: Git Flow, containers, GitHub Actions, Ansible, releases, retrospectives, adages.

On the day

  • Arrive on time or early. Seats are assigned.
  • Paper exam. Pen or pencil, pen preferred. No notes.
