Computing environments and bit rot

Bit rot ("does code rot?"): the code's bytes do not change, but the world around it does. Dependencies release breaking versions, OS packages move, interpreters are upgraded, services are retired. So code that ran last year fails today, and "often, the default experience is failure". Lecture's conclusions:

  • Managing environments is hard. Programmers must act as "end-user system admins", and most "it won't run" replies are about dependencies.
  • "Software on your machine has no real value." A billion-dollar idea that only runs on your laptop is worth $0 until it runs somewhere users can reach it.
  • Think of a computing environment = configuration + code: the code plus its dependencies, environment, ecosystem, stakeholders and users.

A Dockerfile is a direct answer to bit rot: it writes the environment down so it can be rebuilt. Note the trade-off the workshops raise: alpine:latest always gets the newest base (and may break later); a pinned version is stable but ages.

Vocabulary from the slides

Virtual machine (Popek and Goldberg, 1974)
"An efficient, isolated duplicate of the real machine."
Host / hypervisor
The operating system running on the physical machine.
Guest
The operating system running inside the virtual machine.
Virtual machine monitor (VMM)
Helps run the guest on the host; implements the virtualization interface and enforces the illusion of isolated machines.
Privileged instructions
I/O, memory address mapping, loading system registers, switching kernel/user mode. These are what a VMM must intercept.
Headless
No graphical interface. Headless VMs, micro VMs and containers are infrastructure you "build, use, and throw away". Classic VMs are fully loaded, graphical and heavyweight.

How a VMM runs guest code

TechniqueIdeaExamples
Full emulationInterpret every guest instruction in software (fetch, decode, switch). Emulates CPU, memory, disks, network. Simple but slowBochs, video-game emulators
Trap-and-emulateRun safe instructions directly on the CPU; privileged ones trap to the VMM, which emulates themSystem/370
Binary translationRewrite unsafe instructions into safe calls before running themQEMU, VMware, VirtualBox
Hardware-assistedCPU adds a guest mode and new instructions (VT-x), so the VMM is faster and simplerKVM, ESXi, Hyper-V
ParavirtualizationPatch the guest OS so it cooperates with the VMMXen
OS-level virtualizationThe OS itself virtualizes resources per process group. Not full virtualization of a systemContainers

Trend from the slides: AWS moved from Xen (paravirtualization) to KVM (hardware-assisted). Firecracker micro VMs are still a foundation of AWS.

Activity prompt and a model answer

Self-checkHave you ever had issues with running code? What was the cause?
A typical answer: a project that ran last semester now fails because a library released a breaking version, the interpreter was upgraded, or a package is not installed on this machine. The cause is the environment, not the code. The fix is to write the environment down (Dockerfile, pinned versions, a playbook) so it can be rebuilt.

Check yourself

Self-checkIf code does not wear out, why does it "rot"?
Because software depends on an ecosystem (libraries, OS, services, hardware) that keeps changing. The code is the same but its assumptions stop being true.
Self-checkWhy is full emulation slow, and what do the optimizations do about it?
Every guest instruction is interpreted in software. Trap-and-emulate and binary translation let safe instructions run directly on the CPU and handle only privileged ones specially; hardware-assisted virtualization moves that support into the CPU.
Self-checkGive the use case for bare metal, headless VMs, containers and micro VMs.
Bare metal: desktop, mobile, embedded, efficiency, CI harness. Headless VMs: general-purpose computing services. Containers (OS-level): self-contained processes. Micro VMs: embedded appliances such as Docker for Mac and WSL.

Practice

The exam has three question types: true / false with corrections, matching concepts, and naming the tool from a code snippet. "Self-check" and "Read the code" items are for understanding only. On true / false, underline the wrong word and write the fix; a plain "not" earns nothing.
True / FalseContainers virtualize the hardware, so each container runs its own kernel.
False. Change Containers to Virtual machines (or: containers virtualize the operating system and share the host kernel).
True / FalseBit rot means that source code files become corrupted on disk over time.
False. Bit rot is code failing because its environment and dependencies change around it. The code itself is unchanged.
True / FalseThe guest is the operating system running inside the virtual machine.
True. And the host (hypervisor) is the OS on the physical machine.
Self-checkName one advantage of a VM over a container and one advantage of a container over a VM.
VM: stronger isolation and it can run a different operating system or kernel than the host. Container: much lighter and faster to start because it shares the host kernel, so you can run many more per machine.
